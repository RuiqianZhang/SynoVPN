# 安装、升级和网络

## 要求与安装

当前实机目标 SA6400 / DSM 7.4.1-90080 Update 1，套件架构 epyc7002。先安装并运行 Container Manager。网络需允许首次获取 Alpine 基础镜像；NAS 内核需支持 policy-based IPsec、iptables 与 IPv4 转发。安装到健康存储空间，避免与其他占用 UDP 500/4500 的 VPN 服务共用端口。

1. 在 DSM 套件中心选择“手动安装”，上传 SPK，按自己的同次 SHA-256 校验文件核对来源。
2. 确认第三方套件提示，填写公网 VPN 域名、DSM HTTPS 地址、允许访问的内网 CIDR、DNS、VPN 池和允许用户组。
3. 完成后从 DSM 主菜单打开 SynoVPN，确认用户身份和“服务已就绪”。无需手动创建容器或 Compose 项目。

当前部署参数（供理解，不应原样用于另一台 NAS）：

| 参数 | 当前值 |
|---|---|
| VPN 域名 | nas.hnzyy.ltd |
| 公网 DSM HTTPS 地址 | https://nas.hnzyy.ltd:888 |
| NAS 内网地址 | 192.168.10.10 |
| 内网 DSM 入口 | https://192.168.10.10:5001 |
| 允许内网 | 192.168.10.0/24 |
| DNS | 192.168.10.30 |
| VPN 地址池 | 10.77.0.0/24 |
| 允许组 | users |

公网域名应解析到可接收入站 UDP 的公网地址。NAS 内网 IP 在 DSM 网络界面设置或由 DHCP 分配；VPN 池由引擎给客户端分配，三者含义不同。

## 自动容器运行

SPK 的 `packaging/conf/resource` 使用 DSM 官方 docker-project worker。安装/启动套件时，DSM 构建并启动项目 `synovpn-engine`，容器同名，当前镜像 `synovpn-engine:0.5.0-1`。门户用普通套件账号运行；容器使用 host 网络和明确网络能力，不使用 privileged 或 Docker socket。重启策略为 unless-stopped。

正常安装不需要人工去 Container Manager 创建/启动容器。NAS 开机后还依赖套件和 Container Manager 服务正常启动。早期升级出现过一次启动未就绪，套件中心“修复”后恢复，因此不能承诺任何异常都无需人工恢复。不要单独停止生产容器后期待 unless-stopped 自动撤销这一人工停止状态。

## 对外端口

| 协议 | 公网端口 → NAS 端口 | 用途 |
|---|---|---|
| UDP | 500 → 500 | IKEv2 协商 |
| UDP | 4500 → 4500 | NAT-T / VPN 数据 |
| TCP | 当前 888 → 已有 HTTPS 门户入口 | 远程登录和扫码领取 |

路由器转发目标为 NAS；DSM 防火墙也需放行。强制 ESP-in-UDP，无需另开 ESP/UDP 1701。原生客户端使用标准 UDP 500/4500，不应改成其他公网端口。HTTP 反向代理不能替代 UDP 转发。不要开放引擎控制端口 18447；它只监听本机。

## 持久数据与备份

- `/var/packages/SynoVPN/etc`：固定配置、门户加密密钥及引擎访问令牌，敏感。
- 套件 `var`：SQLite 数据、审计、日志、Web 运行目录。
- 命名卷 `synovpn-engine-state`：CA、服务端密钥、设备撤销账本/CRL 等，敏感。

备份时先停止套件，通过 DSM 支持的方式完整保存套件配置/数据及引擎命名卷，保留权限并加密备份。不要只备份数据库或 CA；丢失撤销账本不能靠新建空账本恢复。不要在备份工具截图或聊天里公开这些文件。

配置由首次安装固定。更新向导重复显示的输入不会覆盖已有 config.json；首次启动后引擎还会固定自己的配置。此版本没有在线修改网关参数/迁移配置的 UI。修改已有部署前需制定包含门户和引擎配置的迁移方案，不要只改一份文件。

## 升级与卸载

升级前备份，以相同架构 SPK 在套件中心升级，随后重开页面，检查身份、网关和设备列表。升级可能短暂断开 VPN。旧 0.1 口令认证迁移会停用旧口令设备，必须重新创建证书；不能将旧密码转换成证书。

卸载涉及 DSM 数据保留选项与容器卷，不承诺自动保留；先完成完整备份再按意图操作。不要删除 `synovpn-engine-state` 来“修复”连接问题。不要在 Container Manager 清理当前引擎项目、镜像或卷。测试构建项目与生产项目必须分开。
